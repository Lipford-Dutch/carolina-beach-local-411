# Support

## Product problems

Use a GitHub bug report for reproducible site problems. Include the browser,
device, affected route or control, and the smallest reproduction steps.

## Content corrections

Use the vendor/source update template and include a first-party source whenever
one exists. Town schedules, parking rules, business hours, and seasonal events
must be rechecked before publication.

## Security reports

Do not open a public issue for a vulnerability. Follow `SECURITY.md` and use the
repository's private vulnerability reporting channel.

## Hosting incidents

The Sites deployment, GitHub Pages project home, and Hostinger package are
separate delivery targets. Identify the affected target before troubleshooting
and record the exact deployed commit.
